# Workflow: redesign

1. Audit audience, hierarchy, navigation, content, visual language, responsive behavior, accessibility, and task friction.
2. Separate the behavior, brand, architecture, and content that must remain from what the user wants changed.
3. Identify the highest-impact issues and opportunities; inspect existing components and constraints.
4. Use [references/art-direction.md](../references/art-direction.md) to consider design approaches and select the one that fits the product and requested change. Share one recommendation by default, not a menu of concepts.
5. Get input on unresolved consequential direction or scope decisions; do not ask for approval on settled or routine details.
6. Map existing components and functionality to the new direction. Preserve routes and data flows unless a change is requested.
7. Implement incrementally, then inspect the result and run relevant responsive, functional, and accessibility checks when available.
8. Report what changed, what was retained, checks performed, and what could not be verified.
