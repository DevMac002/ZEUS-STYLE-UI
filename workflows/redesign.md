# Workflow: redesign

1. Audit the current experience: audience, hierarchy, navigation, content, visual language, responsive behavior, accessibility, and friction.
2. Separate constraints to retain from elements intended to change.
3. Identify the highest-impact problems and opportunities.
4. Propose context-sensitive directions with trade-offs; do not assume a redesign means replacing everything.
5. Obtain approval for the chosen direction before a substantial implementation.
6. Map existing components and functionality to the new design; preserve data flows and routes unless change is approved.
7. Implement incrementally.
8. Compare the result with the agreed direction and run available functional, responsive, and accessibility checks.
9. Report retained behavior, changes, tests, and residual risks.
