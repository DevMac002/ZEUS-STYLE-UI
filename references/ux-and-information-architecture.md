# UX and information architecture

- Start with user goals and the primary task, not with decorative sections.
- Organize content in a hierarchy that supports scanning and decision-making.
- Use familiar patterns when familiarity lowers friction; innovate when it adds meaningful value.
- Keep navigation labels clear and distinguish primary from secondary actions.
- Make forms understandable with labels, instructions, validation, error recovery, and success feedback.
- Form validation: prefer inline validation, but do not validate before the user has finished the field (avoid premature errors); remove the error as soon as the field is corrected; show a summary of errors at the top of the form on submit in addition to inline messages, never as the only indication; move focus to the error summary; link each summary item to its field. Error messages must say what happened and how to fix it, in plain language, next to the field. Avoid disabled submit buttons as the only validation mechanism—let users submit and receive guidance.
- Provide loading, empty, error, disabled, and success states where relevant.
- Avoid dark patterns, deceptive urgency, hidden costs, confusing opt-outs, or inaccessible interactions.
- Use realistic content to test line lengths, density, and edge cases.
- For data-heavy interfaces, prioritize comparison, filtering, legibility, and useful defaults.
- For conversion-focused pages, communicate value, credibility, objections, and next steps without manipulative claims.
- Do not invent business facts, metrics, testimonials, customer logos, or product capabilities.
