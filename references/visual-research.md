# Visual research and reference intelligence

Systematic research before and during design. Use it to understand what works, not to copy an interface.

## Establish project context first

Before searching, identify as far as available:
- Product type: SaaS, dashboard, portfolio, e-commerce, landing page, mobile app, internal tool, editorial site, or other.
- Theme, industry, and target audience.
- Main goal and expected user action.
- Platform: web, mobile, tablet, or cross-platform.
- Detected stack.
- Maturity: idea, prototype, redesign, or existing product.
- Constraints: branding, deadlines, accessibility, performance, SEO, browsers, devices.
- Desired art direction, existing references, and creative freedom.

If purpose or scope is materially unclear, ask 2–3 targeted questions first; ask more only if important ambiguity remains.

## Research rules

1. Search for examples matching the current theme, platform, and product function.
2. Examine several different references — ideally 5–10 when accessible sources allow.
3. Prefer real interfaces, documented design systems, and recognized projects over mockup-only shots.
4. Compare multiple visual approaches; do not default to the first trend found.
5. Analyze composition, grids, spacing, color, typography, interactions, animation, navigation, hierarchy, and component states.
6. Decide what adapts to this project and what does not fit its audience or constraints.
7. Provide direct links to consulted pages with a brief note on each reference's value.
8. Distinguish observed trends from recommendations grounded in documented standards.

**Honesty rules:** use available search and browsing tools. If a page or image is inaccessible, try another source or ask the user for a screenshot. Never claim to have examined a reference that was not actually retrieved. Never invent URLs, statistics, or visual details.

## Adapt inspiration to the current theme

Research must change with every project. Examples:
- B2B SaaS: information hierarchy, dashboards, tables, filters, controlled density.
- Premium e-commerce: photography, merchandising, typography, trust, conversion.
- Creative portfolio: editorial composition, identity, storytelling, experimentation.
- Financial app: legibility, data, trust, safety, error prevention.
- Health app: clarity, accessibility, confidentiality, reassuring language.
- Mobile app: touch navigation, gestures, ergonomics, platform conventions.
- Cultural or artistic product: graphic freedom, expressive typography, visual narrative.

These are not rigid templates: always adapt choices to the real brief.

## Analysis and synthesis

For each retained reference, analyze:
- Identity and art direction.
- Layout and grid system.
- Visual hierarchy.
- Color palette.
- Typography and type scale.
- Spacing and proportions.
- Shapes, radii, borders, shadows, depth.
- Iconography and illustration.
- Photography, textures, image treatments.
- Components and interaction patterns.
- Responsive behavior.
- Accessibility and legibility.
- Strengths, limits, and relevance for this project.

Then synthesize into:
1. Recurring principles observed.
2. Interesting ideas worth adapting.
3. Optional trends.
4. Practices to avoid.
5. Original elements to create for differentiation.

Do not copy an interface. Use references to understand the principles that work, then create an original, coherent direction. See `references/art-direction.md` for concept generation and `references/configuration.md` for source precedence.
