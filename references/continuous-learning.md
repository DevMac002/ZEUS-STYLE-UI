# Continuous learning and design intelligence

When the user asks to integrate a lesson, or repeated validated experience reveals a reusable improvement, update this skill so the next session starts smarter. Do not edit the skill after every project by default.

## Three knowledge levels

Organize knowledge strictly by level. Never mix them.

**Level 1 — Universal principles:** accessibility, legibility, maintainability, feedback, coherence, error prevention, honest reporting. These apply to every project.

**Level 2 — Platform and stack rules:** web, iOS, Android, React, Vue, Next.js, Flutter, React Native, and their documented conventions. These apply to matching targets only.

**Level 3 — Project preferences:** brand, palette, art direction, components, editorial tone, and specific constraints. These belong to one project; never promote them to global defaults without justification.

## What to improve

When files are accessible, update the appropriate ones:
- `SKILL.md`: role, core rules, workflow.
- `config/`: global behavior, platform preferences, visual preferences, quality gates.
- `references/`: palettes, typography, accessibility, responsive, patterns, standards.
- `workflows/`: creation, redesign, research, validation, delivery.
- `tests/`: new cases and acceptance criteria.
- `README.md`: usage instructions.
- `CHANGELOG.md`: change history.

## Integration rules

1. Every improvement must be justified by a source, an observed problem, a test, or a verifiable experience.
2. Deduplicate: merge with existing rules instead of adding parallel ones.
3. Preserve compatibility: do not break existing configuration or workflows.
4. State limits: note when a rule is contextual or unverified.
5. Do not turn a passing trend into a universal rule.
6. Do not replace existing user preferences without a reason.
7. Prefer plain, vendor-neutral language; keep client-specific notes in an adapter layer.

## Improvement cycle

1. Understand the current project theme and goals.
2. Inspect the current state of this skill.
3. Research fitting references from credible design sources.
4. Examine relevant official standards and current practices.
5. Compare approaches and select the useful principles.
6. Design or improve the art direction and design system.
7. Integrate validated learnings into the skill.
8. Test and document the changes.
9. Keep universal rules, technical rules, and project preferences separated.
10. Repeat on the next session.

**Final objective:** make Web Design Engine an evolving skill that can research, understand, select, adapt, create, implement, and verify professional interfaces for the real project theme — without sacrificing originality, accessibility, code quality, or maintainability.

For a substantial learning update, use `templates/session-report.md` when a report would help or the user requests one.
